错误日志里大量如下 Warning：



```
InnoDB: Warning: a long semaphore wait
--Thread 140570431108864 has waited at btr0cur.c line 528 for 241.00 seconds the semaphore:
X-lock on RW-latch at 0x7fd9142bfcc8 created in file dict0dict.c line 1838

```

分析过程
----


查看监控图，发现 Spin Waits 和 OS Waits 相当高，查看 MySQL Documentation 在 [14\.5\.3 Adaptive Hash Index](https://dev.mysql.com/doc/refman/5.7/en/innodb-adaptive-hash.html) 这里查到了如下：


* You can monitor adaptive hash index use and contention in the `SEMAPHORES` section of `SHOW ENGINE INNODB STATUS` output. If there are numerous threads waiting on rw\-latches created in btr0sea.c, it might be useful to disable the adaptive hash index.


在 MySQL 5\.7 之前的版本，由于并发请求过多，自适应哈希索引会造成大量的锁争用，进而堵塞很多进程，最终导致MySQL崩溃重启。


解决方案
----


找到原因后，通过参数 innodb\_adaptive\_hash\_index 禁用了自适应哈希索引（默认为开启），最终问题得到了解决。



```
set global innodb_adaptive_hash_index = 0;

```


> 注：如果是 MySQL 5\.7，除了禁用自适应哈希索引，也可考虑增加自适应哈希索引的分区数量，或者升级服务器规格，增加并发处理能力，减少锁等待。
